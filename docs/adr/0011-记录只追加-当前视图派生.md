# 0011. 记录只追加，当前视图派生

**Date:** 2026-10-20（决定形成于 2026-10-17 至 10-20）
**Status:** Accepted

## Context

原型的述线页由脚本整页重画、按播出日期排，看着是对的。2026-10-17 用户问：先跑新集、再补旧集会怎样？对照原型查出五处不对：

1. 述线页时间线设计成只追加，补跑的旧集会排到最后。
2. 述线的「首次出现」只在开线时写，后来挂上更早的集不往前改。
3. 初筛页的「新 / 续 · 上次 X」靠扫这条述线里的集来判，补跑一集比所有集都早的旧集时找不到，脚本报错。
4. 挂述线的 prompt 没交代「上次出现」可能晚于本集播出日期。
5. 回挂的时间范围只往前看，补跑的旧集看不到比它晚、没挂的片段。

同一类问题在别处也会出现：Obsidian 页面是生成物，人在生成的节里写的字会被下一次重画覆盖；深加工的判定以后会被新证据改，直接改写旧判定就丢了「当时为什么这么判」。

## Decision

1. **记录只追加。** 开线、挂法（含加挂、改挂、回挂）、合并拆分改挂的执行、深加工轮次、判定，都是带时间的追加记录，不在原处改。要改就追加一条新记录盖过旧的，旧的留着看得见。
2. **视图由代码从记录派生。** 述线页的时间线、底细行、关联述线节、现状，初筛页的全部内容，都在重画时从记录算出来；任何排法都能从记录重算。人写的东西放在生成的节之外：EP 笔记的批注写在自动块外，述线页的字写在节外，「我的判断」落 `50-Mine/`。
3. **时间分开记。** 首次出现 = 开线那晚，不往前改；上次更新 = 最近一次给这条述线加素材的那晚；每条素材另记它自己的播出日期与节目内时刻；每条挂法记挂上那晚和怎么挂上的（4b / 4c 回挂 / 回顾整体 / 人）。述线页默认按播出日期排，由程序做；按所说的事发生的时间排的事件脉络是深加工的产物，由模型做、联网核日期。
4. **标签从记录来，不扫集。** 初筛页的「新」= 今晚开的线，「续」后面写述线记录里的上次更新。
5. **补跑按播出日期插入**；回挂按播出日期前后都看。
6. **判定同此规矩。** 深加工的判定与评估可以被新信息推翻，办法是追加一条新判定（哪天、原判、新判、因什么），不擦旧的；用到它的评估按依赖标过期，细节归说法台账的 ADR（0013，待第 7 到 10 步核完）。

## Rationale

**追加的记录才补得回来。** 五处毛病都出在「当前状态」被当成了唯一事实：改了首次出现就不知道开线那天是哪天，整页重画就不知道哪条是补跑进来的。记录带时间只追加，补跑、重排、回溯都是从记录重算一遍的事。

**视图派生才敢重画。** 页面每晚要重画，人写的字只有放在生成区之外才不会被盖掉；反过来，生成区里就不该有人工痕迹，这样代码可以放心整节重写。ADR 0002 的原则在这里是同一条：状态在文件里，显示是免费的。

**时间要分开，是因为它们回答不同的问题。** 「这条线是哪天开的」「最近哪天加过东西」「这段是哪天播的」「这段是哪晚挂上的」四个日期各有用处，合成一个就全错；用户定 MVP 先把每段的播出日期记全，排法日后有数据再调。

**判定也不能擦。** 核查是 AI 初判（红线 4），以后会被更好的来源、人的复核、原来源撤稿推翻。擦掉旧判定就看不出判断怎么变的，也没法顺着依赖通知用过它的地方。情报分析标准要求「说明判断变了还是没变」，追加盖过正是这个要求的实现。

## Consequences

- 挂法记录的字段定下来：集号、述段 id、播出日期、节目内时刻、挂上那晚、怎么挂上的；`threads.json` 的首次出现、上次更新按本 ADR 的语义写。
- 页面渲染改成记录的纯函数；第 4、5 步两张票的验收加一个合成样例「先跑新集、再补旧集」（两集假数据，晚的先跑），机判时间线顺序、初筛页标签、回挂两边都看到；不单独开票。
- 排法以后要调时只改渲染，数据不动。
- 深加工的说法台账、问题的账沿用同一规矩：改判追加、当前视图派生（0013 细化）。
- 人要改机器的结论（周末复核），也是追加一条「人改」记录，渲染不覆盖（SPEC §9 的「人改过的核查判定是永久正本」照旧）。
