# 0001. 时间戳跳播自研 Obsidian 插件，不用现成的 timestamp-player

**Date:** 2026-08-03
**Status:** Accepted

## Context

SPEC §5.1 的断言行带 `录音时间戳`，SPEC §5.3 规定格式为 `HH:MM:SS`。阅读断言时要能点一下时间戳直接听主播原话——**这是「回到原话」这条产品承诺的最后一公里**，没有它，`source_quote` 就只是一段无法验证的文本。

社区插件 `timestamp-player` 表面上正好做这件事。实测（`docs/prototypes/timestamp-seek/`，A–G 七轮）后确认它撑不住，有三个源码层面的硬限制：

1. **音频绑定按 DOM 位置，不按数据。** `findAudioForBtn` 沿文档顺序找「我上面最近的那个 `<audio>`」，和这条断言出自哪一集无关。跨集查询表里整张表会全播同一个音频：点 EP07 的 `04:00`，播的是 EP01 的 4 分 00 秒——**有声音、位置也对，就是集数错了，还不报错**（实测 D-1 确认）。
2. **正则只认 `MM:SS`。** `00:29:00` 被解析成 29 **秒**。SPEC §5.3 用的正是 `HH:MM:SS`，**静默错 60 倍**（实测 A-2 确认）。
3. **`activeBtn` 跟播放进度走。** `onTimeUpdate` 每秒约 4 次把 activeBtn 重设为「最后一个 seconds ≤ 当前进度」的按钮——它假设笔记是逐字稿、时间戳递增不重复。我们的断言表两条都违反，导致「点同一个按钮暂停」失效。

第 1 条是绑定模型问题，换任何写法都绕不过。

考虑过的替代路径：

- **在 EP 笔记底部放 dataviewjs 块自绘按钮**：能跨集、能吃 `HH:MM:SS`（实测 C-3 / D-2…D-5 全过），但断言行本身不可点，要滚到底下另一张表里去点。人否决：读到哪一行就该在哪一行点。
- **patch timestamp-player 的 main.js**：它是压缩产物，改起来不可读，且会被插件更新覆盖。

## Decision

自研 `story-machine-timestamps`，源码在 `obsidian/story-machine-timestamps/`（纯 CommonJS，无构建步骤）。停用 `timestamp-player`。

关键设计：

- **音频按数据绑**：读笔记 frontmatter 的 `音频:`，经 `metadataCache.getFirstLinkpathDest` → `vault.getResourcePath`。与 DOM 位置无关。
- **没声明 `音频:` 的笔记完全不介入**——既是开关，也是防线。
- **限定符 `EP01@60:00`** 覆盖单条时间戳的归属；反引号 `` `05:00` `` 是逃生舱。正文里提到别集时间轴用得上。
- **跳过 Dataview 查询块**：查询结果的行可能来自别的集，本插件只认「本笔记的 frontmatter」，接管了就会绑错。**跨集阅读面走 dataviewjs 自绘。**
- **播放器插件自造**（右下角浮动条），不去 DOM 捞 `![[x.m4a]]` 嵌入——嵌入是懒加载的，不在视口里根本没有 `<audio>` 元素。
- **事件委托 + `pointerdown`**，按钮信息存 `data-sm-*`；配 MutationObserver 补画。Dataview 会在 post processor 跑完后重画 inline field 把按钮抹掉，且 mousedown/mouseup 落在不同节点时 `click` 根本不触发。

## Rationale

**为什么值得自己写：** 需求（点断言行的时间戳听原话）和插件的模型（读逐字稿时高亮跟播）根本不同，不是配置差异。而实现成本很低——约 250 行、无构建步骤、`timestamp-player` 的源码本身就是可读的参考实现。

**为什么保留 dataviewjs 那条路：** 跨集表里每一行的音频归属来自**行**，笔记内时间戳的归属来自**笔记**。两者信息来源不同，硬要一套代码通吃就会退化成按 DOM 位置猜——那正是 timestamp-player 出局的原因。分工是结论，不是妥协。

**副作用（好的）：** `HH:MM:SS` 原生支持，**SPEC §5.3 不必为迁就插件而改**。改 SPEC 去适配一个撑不住跨集场景的插件，本来就不划算。

## Consequences

- 阅读面从「Obsidian 原生 + 现成插件」变成**项目维护的一段代码**，进 git、有版本。Dataview 内部渲染顺序变化可能使其失效——MutationObserver 补画降低了这个风险，但没消除。
- **要维护两条渲染路径**（2026-08-13 补，v0.4.0）：初版只注册了 `registerMarkdownPostProcessor`，而那个东西**在实时预览里根本不跑**——Obsidian 的实时预览用 CodeMirror 6 自己画正文，post processor 只在阅读视图和导出时经过。于是时间戳只在阅读视图可点，而阅读视图**改不了字**。阶段 3 审核恰恰要一边改草稿一边点时间戳听原话，这个组合在初版里是走不通的：想点就不能改，想改就点不了。补了一个 CM6 `ViewPlugin`（装饰 + `atomicRanges`，光标落进某个时间戳时让位露出原文）。两条路径共用 `TS_RE`、`resolveAudio`、`makeBtn`、`jump`，分叉只在「怎么找到那段文本」——阅读视图走 DOM TreeWalker + CSS 选择器排除，实时预览走可视区文本 + 语法树排除。**`@codemirror/*` 的 require 包在 try 里**：真拿不到时只丢掉实时预览那条路，不能让整个插件加载失败、把本来能用的阅读视图也带走。
- 新增一条笔记约定：**EP 笔记 frontmatter 必须有 `音频:`**。生成 EP 笔记的脚本要写这一行。
- 音频文件必须在 vault 内（`getResourcePath` 的前提）。SPEC §6 的目录结构**漏了 `_assets/`**，而 §6.1 的 frontmatter 已经在引用 `../_assets/EP01.transcript.json`——这处自相矛盾要补。
- 装机步骤多一步：拷三个文件进 `.obsidian/plugins/` 并在 `community-plugins.json` 里登记。见插件 README。
