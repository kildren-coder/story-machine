# 0013. 说法台账全系统一张：核一次被引用，证据全记，改判追加传播

**Date:** 2026-10-21（决定形成于 2026-10-16 至 10-21）
**Status:** Accepted

## Context

原型（2026-10-09）的核查是一条述线一次调用：把挂在这条述线上的全部「可核查的说法」喂给 sonnet，每条判 ok / warn / bad / none，附链接，产物是这条述线自己的 `check.json`，渲染成一张台账。跑通了，判得也不差，抓到了学位、选举结果这类硬错。2026-10-21 按核实清单第 7 步核了一遍，形状有五处不对：

1. **核什么。** 按「L2 列了多少条就核多少条」。拿默认问题「主播的论点站不站得住」把两集 32 条说法重排一遍诊断力：能分辨论点的 3 条，有点用的 5 条，背景 16 条，离题 7 条（直播间人数、与主题无关的几国人口、一个假设性举例），重复 1 条。反过来，最能分辨论点的 8 句话根本不在 claims 里：论点本体只在原话里，评价句的事实核心没人核，主播自标「如果没记错」的数字被 L2 的「推测不列」排掉，三条预测没有去处。四问那一层顺手查了其中几句。按条数全核，三分之二的额度花在背景和闲谈上。
2. **怎么判。** warn 档混了「事实差多少」和「影响不影响论点」两件事，9 条 warn 按事实本身看有 6 条就是小不实。一条说法里常有好几个命题（甲是现任、乙是现任、某派推甲乙搭档），一个判定装不下。模型自承有数字来自记忆、链接附的是百科条目；没依据的一条拿视频网站的搜索页凑「每条必带链接」。
3. **怎么记。** 一条述线一份文件：同一件事在两条述线下各核一次，核过的没法被引用，两集里两个说话人口径对不上的地方只在笔记正文里写了一句「没对齐」，没有落成字段，也没法传播。
4. **花多少。** 一次 32 条约 1 美元、220 秒，其中一半是联网搜索：Claude Code 把 WebSearch 派给 haiku 子代理，40 次搜索占 47%，而信封里的搜索计数器记的是 0。
5. **机检。** 把 65 个不重复链接逐个请求：54 个正常，9 个被反爬挡住返回 403（劳工统计局、参议员官网、一家日报、一个大学档案馆），1 个页面已撤，1 到 2 个超时。依据是对的，机器打不开。

这期间定下的方向：10-16 用户认可七条改法（说法加 type / stance、五档判定、引证机检、先查核查库、来源分类型不打分、小金标、述线内去重）；10-17 定事实核一次、意义各做，按播出当时判，三种情况才重核；10-20 定问题的账、记录只追加、改判按依赖传播、本地检索找同一件事（ADR 0011）；10-21 两轮定下本 ADR 的具体形状。远景 #92（真伪按贝叶斯更新）明确 MVP 不碰，只要数据模型别堵死。

## Decision

1. **全系统一张说法台账，只追加。** 不按述线分文件；述线页的台账节、深加工页的「重大事实偏差」节都是从台账派生的视图（ADR 0011）。台账的工作项是**命题**：原子、自足（「他」换成名字，「新增两席」补成「某年某月初选新增两席」）、稳定 id、记派生自哪段哪句；一条说法可拆成几个命题各一行。列假设那一步除了给诊断力，还从论点、评价、预测里**派生待核的事实**，标派生自哪段。
2. **判定四态，另记把握与现在。** 判定只回答「事实对不对」：有据 / 不实 / 有争议 / 查不到。按播出当时判，不因世界后来变了而改；核时已变的写进「现在」字段，之后再变走「后续」行。**过时不做档。** 有争议 = 证据够了却定不下来，必带原因二选一：来源相左 / 口径不一；价值之争不进核实。**把握**高 / 中 / 低加原因：一手或两处独立来源为高；单一来源、口径不一、机检未达、只有英文二手报道而没有当事方语言或一手来源，为中或低。把握是对判定的把握，不是真伪概率（#92）。数字差一成以内算有据并写实际数。述线级的「整体 ok / warn / bad / none」徽标作废，整体评估归推理层（0012）。
3. **核什么由诊断力定，不按条数。** 列假设给每条命题标关联假设、方向、诊断力高 / 中 / 低 / 无；代码按高到低排队，同级内断言先于转述先于推测，无不进队列；按 token 切批，没核到的留队列，台账先显示「待核」；额度是面板上的旋钮（0014）。**核实的模型不看假设与方向**，诊断力只给代码排队用；prompt 里给命题、原话那句及前后各一句、述段标题、播出日、说话人、stance、转述自；问题可给，假设不给；语境不求多，指代由命题写自足来解。
4. **证据一律全记，分门别类，立场先记不析。** 每个命题把检索到的**全部**来源都记，不只记模型用到的，代码从搜索结果写、不花额度。每条来源：网址、域名、语种、地域、发布时间、署名或通讯社、文中引的上游、来源类型。模型用到的那几条再加引文片段和方向（撑 / 反）。来源类型五类：一手 / 媒体报道 / 评论 / 社媒视频 / 汇编（百科、Ballotpedia 一类）。**社媒视频打折**：只靠它撑着的命题不能判有据或不实，把握最高给低；例外是当事人或机构的官方账号，在「他说过什么」这类归属说法上算一手，记账号名与是否官方。每个命题另记检索结果里社媒视频占了几条、哪些平台。**来源表**按域名记：类型、立场一句、语种、地域、人确认、首见日；同一域名的立场只由模型写一次，人周末可改，之后代码套用。独立性按上游归组、传播顺序按发布时间，MVP 只记不算。
5. **检索在模型外，语种跟当事方走。** 代码按命题生成查询、并行搜、抓前两三页正文，连摘要喂给核实的模型；模型只判断、摘引文片段、指明用了哪条，调用不带搜索工具。检索语种由当事地区定（列假设标地区，代码查地区到语种的表），英文总在但排在当地语言之后，作用是覆盖不是定论；检索词由列假设那次调用一并写成当地语言。搜索结果缓存，同一命题重核不再搜。检索层用 AnySearch（第三方托管搜索 API，账号由用户注册、代码做 key 池），Claude 自带 WebSearch 留作退路。只发命题文本，不发原话。
6. **引证机检三态，宁缺勿编。** 机检在代码已抓到的文本里找引文片段：过 / 未达（403、超时、页面已撤：判定不变，标「未机检」，周末人点开）/ 不符（页面打开了找不到片段：降查不到，把握降低）。查不到可以没有链接，但必须写搜了什么、搜了哪些语种；其余三态必须有链接和引文片段。判不实须两处独立来源（不同上游、非汇编）或一处一手，不够降有争议。模型自带的知识不作依据。
7. **说法匹配：核一次，被引用。** 核之前代码对每条命题去台账检索最像的 5 条（实体键加向量，k 是起步值，随台账长大再定），候选连判定一起进 prompt，模型每条三选一：同一件事（引用旧判定、不重核，台账写「同 → 某条」）/ 相关（只记链接）/ 冲突（两边都标，初筛页出一行预警，问题的账记缺口）。跨述线同此。10-17 定的三种重核情形各有落点：对不上 = 匹配判冲突；上次查不到或有争议过了一段时间 = 30 天重试队列；在这条述线里其实是另一个命题 = 列假设派生新命题。
8. **改判追加，按依赖传播。** 判定可以被更好的来源、人的复核、原来源撤稿推翻，办法是追加一条新判定（哪天、原判、新判、因什么），旧的留着。要分清三种「变」：改判（当时判错）、后续（世界后来变了，不改判）、证据的意义变（命题没错，但它在推理矩阵里撑的边变了，改矩阵不改台账）。每版评估记用了哪些命题 id；任一改判，用到它的评估标「过期 · 证据变了」，初筛页出预警行。人周末改判也是追加一条「人改」记录。
9. **说话人三项与预测台账。** 说法带 type（事实 / 预测 / 评价 / 转述）与 stance（断言 / 推测 / 转述 / 假设），L2 写、schema 卡；L2 不再因「自标推测」而不列，直播运营数据（在线人数、礼物）不算说法。核实只核事实类；预测进预测台账，记兑现没有、何时兑现。说话人可靠度由代码从台账数条数、不打分、不合成一个字母：一手（本人断言）的有据 / 不实 / 查不到；转述的转对 / 转错 / 查不到；预测的兑现 / 落空 / 未到期。只数诊断力不为无的条目。
10. **不做的。** 不打信用分；不出概率；核查结论不经周末人确认不当定论；先查核查库（ClaimReview 一类 API）另开小票、不卡核实；小金标 30 条是人在真跑产物上做，不进 AFK。

## Rationale

**为什么一张台账。** 事实和述线无关：一个人是不是现任参议员，在哪条述线下核都是同一个答案。一条述线一份文件就只能重复核、不能引用、冲突看不见、改判传不出去；10-17 定的「事实核一次、意义各做」只有一张台账才成立。

**为什么四态不五档。** 核查的人能观察到的状态只有四种：找到同意的、找到反对的、两边都有、什么都没找到；再多的档位是解释不是观察，这一行的基准测试（FEVER 三类加 AVeriTeC 的证据冲突）也收敛在这四个上。过时做成档，同一条的判定会随核的日期漂，说话人三项也数不对；做成「现在」字段，判定稳定，世界的变化照样看得见。「影响不影响论点」是另一轴，归诊断力与推理，不该混进事实判定。渐变真伪的六档是因为不拆命题才需要的，我们拆了。

**为什么诊断力不按条数。** 32 条里只有 3 条真能分辨论点，而最该核的 8 句不在清单里；按条数核是把钱花在背景上、把该核的漏掉。列假设在先、核实在后，核的就是能分辨假设的那几条，这是分析流程的常规顺序，也是 10-20 定的框架在这一步的落法。

**为什么核实不看假设。** 带着假设去核证据，证据就会往假设上靠；整段语境里就有主播的论证，给整段等于把方向给了。原型 32 条没有一条是因为语境少判错的，语境的真问题（指代、范围）由命题写自足来解，不由多给上下文来解。

**为什么证据全记、立场先记。** 用户的方向是把各方面的报道都记下来、分门别类，综合是以后的重点；对报道方立场解析得越清楚，分析能力越强。当地报道有立场，外国报道立场更重，所以一视同仁都记。现在不析是因为没数据，但记录是免费的：搜索结果本来就在代码手里。社媒视频打折是因为它的可信度远不及报道，但它的泛滥程度能侧面反映公众容易被什么误导，所以占比也先记下来。

**为什么检索在模型外。** 原型一半的钱在搜索，而且搜索次数记成了 0、轮数 34；搜索挪到代码里，模型一到两轮，机检在已抓到的文本里找、不用二次抓，结果能缓存，语种能控制。10-21 实测 AnySearch：单条 2 到 6 秒，5 条并行 8 秒，结果带网址摘要日期；中文、阿拉伯文、希伯来文、日文、繁体中文查询都返回当地源，德文返回英文页；整页抓取普通新闻页八成成功，付费墙和反爬站失败，不解决 403。它的位置是检索层，不是判定层。

**为什么语种跟当事方。** 英文材料发行量最大，未必离真相最近；美国的事用英文，台湾的事用繁体中文加英文，加沙的事用阿拉伯文、希伯来文加英文。中文直搜对美国的题返回的是大报的译稿，二手。

**为什么机检三态。** 六分之一的链接机器打不开而依据是对的；「验不过就降查不到」会把正确判定误降。闸门只拦修不了的（页面开了片段不在），打不开的留给人看一眼。

## Consequences

- `SPEC.md` v4.1 写台账的数据契约：命题、判定四态、把握、现在、来源记录、来源表、匹配结果、改判记录、预测台账、说话人三项；§8 红线 4 改成「有据 / 不实 / 有争议 / 过时之外的判定可无链接，但须写搜了什么」；红线 10 补一句：命题文本可发往检索服务，原话不可。
- L2 prompt 与 schema 加 `type` / `stance` / 转述自，删「自标推测不列」，加「运营数据不算说法」（算第 2 步第 10 处改动）。
- 列假设（0012）的输出定下三样本 ADR 要用的：每条命题的诊断力与方向、派生的待核事实、当事地区与当地语言检索词。
- 新部件：检索层客户端（AnySearch、key 池、缓存、按语种生成查询）、机检、台账写入、来源表、说法匹配（与 0008 的本地索引共用向量模型，归检索调研票）；provenance 按模型分列读 `modelUsage`，今天与各集播出日由代码下发、prompt 不含日期。
- 检索调研票加四项：前 5 条里有没有原型用到的那页、整页抓取成功率与超时率、德语覆盖、社媒占比。
- 原型的 `check-<thread>.json`、述线级整体徽标作废；`_pairs/threads/` 里的原始响应留作对照。
- #92 要留的六个钩子（原子命题 id、type / stance、证据独立于判定、判定不覆盖、预测记兑现、相关说法 id）全部满足。
- 按默认走、有数据再调：一批 8 到 12 条、k 取 5、说话人三项的显示、再核规则。
- 核实这一步的调用形状（列假设 → 核实 → 推理 → 反方）归 0012；额度旋钮、并发、与回顾整体错开归 0014。
