# 0015. 人的入口与周末复核：勾就是意图，判断不进系统

**Date:** 2026-10-23（决定形成于 2026-10-19 至 10-23）
**Status:** Accepted

## Context

SPEC v3 §1.2 把人的活分成两列：每天只读日报；周末「确认核查判定（改标签）、在事件笔记的『我的判断』里写自己的东西」。§9 定人改 = 在那条判定后追加 `[人改:: 日期]` 标签，渲染不覆盖。原型（2026-10-09）的第 10 步「周末：扫台账、写判断、理专题」只是示意：让人在每条述线台账的「复核」列写字、在 `50-Mine/` 写判断、人手改一张专题表。2026-10-23 按核实清单第 10 步核了一遍，四处不对：

1. **周末要做的事比三件多，原型一样没有。** 前九步各自转来的：复核（查不到 / 有争议 / 未机检 / 冲突 / 反方点名 / 30 天到期，0013）、回顾整体的审批与提醒（0007 第 9 条五件）、解挂（0007 第 3 条）、指标与预测到期（0012）、词表确认（0010）、来源立场可改（0013 第 4 条）、说话人三项（0013 第 9 条）、关问题、预开述线。
2. **「复核列」与「人手改专题表」都和 0011 打架。** 台账是派生视图，人写进去的字下次重画就没了；述线清单是记录，人手改整张表是改写记录、不是追加。
3. **人的意图没有结构。** 「在复核列写字」让代码去猜人要什么。改成「勾 + 冒号后填固定词」也被用户否决：打勾只表示「有想法」，意图藏在文字里，设计不清晰；意图要结构化、像单选。
4. **阅读量没有预算。** SPEC §1.3 只写了每天的；周末页列多少行、什么先什么后没人定。拿两集的原型产物估第一个周末：待复核约 7 行，回顾待审批 7 条、已生效 4 条，词表待定约 13 行、等批准约 60 行，预测台账盯着 2 条，来源表新见约 40 个域名。

这期间定下的方向：10-19 用户定打勾只是标记、`50-Mine/` 软件永不进；10-20 定记录只追加、当前判定可变、改判按依赖传播（0011、0013）；10-22 第 9 步定收勾只认行首 `- [ ]`、预警勾放行首、`40-Review/` 是周末读的那组页；10-22 至 10-23 第 10 步 A 到 P 十六条逐条定下本 ADR。

## Decision

1. **人碰系统只有五条路，全是勾。** ① **问**：勾「深加工这条」时带的那句问题；关问题 = 深加工页顶部一行「关掉这题」，收勾后问题状态关、不再提议重跑、述线页现状行留着标「已关」。② **复核**：`40-Review/待复核.md` 每条命题下的勾。③ **审批与撤销**：`40-Review/回顾.md` 待审批区与已生效区的勾；解挂算撤销的一种（第 7 条）。④ **开线**：初筛页「没挂的述段」行的「开线：___」，或直接在 `30-Threads/` 新建一页（0007 第 5 条）。⑤ **我提的**：回顾、词表、来源表三页页末的模板勾（合并 / 拆分 / 改说明 / 拿掉挂法；加词 / 删词 / 改词；改 / 加 / 不可信），填了下次运行就执行、不经审批。改述线名不走勾：直接改文件夹名，worker 下次运行登记成改名记录，撞已有名字就初筛页提醒一行、不改。五条之外没有入口：假设表的并入与作废不给人改，想干预就改问题文本或关掉再勾。
2. **勾就是意图：一意图一勾，文字只是附件。** 一行有几种可能的意图，就在那一行下面缩进列几个勾，各一个固定标签；勾后面的文字（链接、检索词、新名字、理由）只是附件，不参与判断意图。代码只认「恰好勾了一个」：没勾 = 没看，下次照列；勾了两个 = 不收，下次重画在那行标「⚠ 勾了两个」；收走后那组勾整体换成一行「已收 · 日期 · 意图」。标签是枚举、解析是纯代码。前端由 `story-machine-pipeline` 插件强制单选：同一父项下的子任务列表算一组，点一个清掉同组其他的，阅读视图与实时预览都要；代码侧「勾两个不收」留作后备（插件没装、手改文件时）。已定的单意图勾不变：「深加工这条」「开线：___」「重跑问 N」「不重跑」「关掉这题」「解挂」。全部意图一览进 SPEC §5「勾的语法」一张表：页面 · 行 · 勾 · 附件 · 收走后写哪条记录。
3. **所有勾都落成追加记录，页面从记录重画。** 人改判定 = `verdicts.jsonl` 一行（种类 = 人改，带日期、原判、新判、依据、备注），SPEC §9 的 `[人改:: 日期]` 标签作废；解挂 = `links.jsonl` 追加「作废于 run · 人」；审批、撤销、我提的 = `threads.jsonl` / `links.jsonl` / `relations.jsonl` 追加；词表确认 = `words/` 的状态改人确认；来源表改 = 追加一条盖过。**人改优先级最高**：之后机器再核同一命题不盖人改，只能追加「后续」行；查到相反证据就标「冲突 · 与人改」回到待复核让人再看。人改照走依赖传播（0013 第 8 条）：用到它的评估标过期、出预警行。
4. **`50-Mine/` 只有人写，模型永不读。** 一线一个文件 `50-Mine/<述线名>.md`，人自由写，不按问题分文件。系统给的只是链接：述线页「我的判断」节一行；深加工页「判断」节末尾一行链到 `[[50-Mine/<述线名>#问 N …|写在这里]]`，文件或标题不存在时人在 Obsidian 点一下就建，软件不建、不读、不写。述线合并时两个文件不动，新线页两个链接都给。人想让系统知道自己的看法只能走五条入口；评估行标「AI 估计」、永不写进我的判断（0012 第 5 条）。
5. **`40-Review/` 是周末读的一组派生页：入口页加六页。** 入口页 `周末.md` 一行一页带数（待复核几行按种类分、回顾待审批与已生效几条、词表待定与等批准几行、预测台账到期待判与盯着几条、来源表本周新见几个域名、说话人），空的页不列，末尾一行「本周系统要你看的共 N 行」。六页各自的勾：
   - **待复核**：每条命题一行（种类 · 判定 · 命题 · 谁 EP@ts · 依据 · 来源 · 链到台账），下面的勾从 维持 / 有据 / 不实 / 有争议 / 查不到 / 作废 / 重核 里去掉当前判定那个，再加「后续：___」（世界后来变了、判定不改，追加后续行）与「改写：___」（命题派生错了，作废本条、按写的句子当新命题重核）。维持 = 人确认，从此不再上这页，查不到的 30 天重试照跑；作废 = 命题标「不核」，从队列与矩阵拿掉；重核 = 立即进核实队列，附件当检索词、链接当候选来源；未机检行勾维持顺带记「机检：人看过」。页末按命题 id 的模板勾，改系统没列出的判定。冲突一对两行各自勾。
   - **回顾**：三节。待审批（合并 / 拆分 / 拿掉挂法 / 改名改说明），一条建议带齐全部连带改动一次点头，勾 同意 / 同意，改成：___ / 驳回；没勾的下次回顾重判一次再列。已生效（整成新线 / 加挂 / 新关联）列到人勾为止，勾 已确认 / 撤销，开线行加「改名：___」、关联行加「改种类：___」；撤销 = 追加作废记录、记撤销一次。计数：本周与累计按类点头 / 驳回 / 搁置 / 撤销，开线满三个月仍只有 1 段几条，没挂的述段本周新增 / 处理 / 留着。页末「我提的」四个模板勾。关联述线进这页：新关系进已生效、改种类与删除进待审批。收勾：那条线在跑或在排就放回待执行并标「等 X 跑完」（0014 第 8 条）。
   - **词表**：三节。待你定（低把握改字、查过未定、规范写法二选一、假设人物段级、黑话进主播层或通用层），勾 确认 / 改成：___ / 原词对，不改 / 不用管；定了、等批准进拼音词表，节首一个「本节全部批准」，**定了的词要人批准才进拼音词表**，改字表显示层不等批准、照套、可撤；我提的（加词 / 删词 / 改词）。说错的不上这页，归核实。
   - **预测台账**：条目从列假设来（预测类假设、type = 预测的命题），没深加工过的述线的预测不进台账；到期须是日期。三节：到期待判 / 盯着 / 已判。勾：盯着的行 改到期：___ / 现在就核 / 兑现 / 落空 / 作废；无到期的行 到期：___ / 作废；已判的行 改为兑现 / 改为落空 / 改为两可。判不出的上待复核，本页只标「到期 · 判不出 · 见待复核」。
   - **说话人**：只看、无勾。每位说话人一块，三项各一行由代码从台账数（0013 第 9 条），只数诊断力不为无、核过的命题，少于 20 条写「样本少」；每项后面「按述线拆」折叠，再给最近 5 条不实或落空的链接。不打信用分；立场一句与常引上游只留字段不填。
   - **来源表**：列本周新见的域名（域名 · 类型 · 立场一句 · 语种 · 地域 · 首见 · 本周用于几条命题），节首「本节全部确认」，每行勾 确认 / 类型改为：___ / 立场改为：___ / 不可信。**不可信 = 降级**：它撑的命题把握降一档、标「来源降级」，判定不自动翻。老域名不列，要改走「我提的」。确认后代码套用、不再问模型；改类型 / 立场 / 降级 = 追加一条盖过，用到它的判定把握重算、评估按依赖标过期。
   每页每次运行重画，行列到人勾为止、不自动消失（待复核第 3 周起标「3 周未看」仍列）。页面节次与行的样子归 SPEC。
6. **不设总量限制与封顶。** 页面按优先级排序只是排、不截断（待复核：冲突 > 反方点名 > 有争议 > 未机检 > 查不到 > 30 天到期；审批：合并 > 拆分 > 拿掉挂法 > 改名改说明；词表：在说法里 > 人名机构 > 出现次数）。入口页的总行数每次运行记进 `runs.jsonl`，人用一段时间拿它定要不要封顶。周末不是固定的日子：页面每次运行都重画，人哪天看都行，勾在下次运行收；只有回顾整体是每周一次（0014 第 8 条）。
7. **解挂只给机器事后生效、没经人点头的挂法，一种意图只在一处。** 4c 回挂：初筛页当天块里的回挂行给「解挂」勾，它是当晚运行的产物，就在当晚那块上收。回顾整体挂上的（整成新线 / 加挂 / 新关联）：回顾页已生效区的「撤销」勾；已生效区不列 4c 回挂，计数节只数「本周回挂 n 段 · 解挂 m」。4b 当晚挂的普通述段行不给勾（一集 50 行加 50 个勾，初筛页就成了待办清单）；觉得 4b 挂错了走回顾页「我提的 · 拿掉挂法：EP@ts 从 A」，下次运行执行、不经审批。收勾三处一样：`links.jsonl` 追加「作废于 run · 人」，该段若再无别的线就回「没挂的述段」（下次 4c 与回顾第 5 件兜底），同段同线记驳回、名字说明没变不再提；解挂照走依赖传播。
8. **到期谁判应验：核实判，不靠人。** 指标、预测类假设、预测台账条目三种到期合一，调度与触发见 0014 第 9 条；到期派生命题进核实队列头，有据 = 应验撑 / 兑现，不实 = 应验反 / 落空；判两可或查不到的上待复核，意图只在待复核一处。判出结果出预警行，重跑由人勾「重跑问 N」或「不重跑」。人在预测台账页能做的只有改到期、现在就核、作废、改判结果。补跑旧集时到期已过的，在深加工那一轮里当场核。
9. **翻旧账不算回顾第六件。** 回顾整体管述线的形状，五件都是述线与挂法；翻旧账是重核判定，归核实的再核规则（0013 第 7 条三种，加人勾「重核」）。MVP 不加「老判定定期抽查」。以后要加就是面板一个旋钮「每周抽查 N 条老于 M 月的诊断性判定」，排序用结构化查询（多老、几个开着的问题在用、是否诊断性、是否单一来源），走核实队列、不是模型调用、不进回顾页。
10. **不做的。** 不打信用分；不给人改把握、改诊断力（都归下一轮模型）、改假设状态（改问题文本或关掉再勾）、拆命题（用「改写」）；立场一句与常引上游只留字段；不设周末预算封顶；回顾整体的 prompt 与插件单选的改动都不进 AFK。

## Rationale

**为什么只有五条路、全是勾。** 红线 7「综合归人」与红线 6「阅读负担」在新形状下的落法：人碰系统的面越窄，系统越能把人的每个动作落成一条记录，事后看得见谁在什么时候改了什么；写字让代码猜意图，是把判断藏进文本。勾是 Obsidian 里零学习成本的动作，收勾是纯文本扫描、零额度，和「深加工这条」「开线：___」一个路数。

**为什么一意图一勾。** 用户的批评成立：打勾只表示「有想法」，意图藏在冒号后面的字里，代码按固定词表解仍是在猜。单选是意图的最小结构：一个标签一个意图，代码只认恰好一个，不猜。页面会变长（待复核 7 行变约 50 行），但每行一眼能看出能做什么；插件把一组勾画成单选是显示层的事，不装插件也能用，和 ADR 0002「状态在文字里、插件只画」是同一原则。

**为什么人改追加、优先、但不静默。** 记录只追加（0011）；人改是永久正本（SPEC §9 原意不变，只是标签换成记录行）。机器再核同一命题查到相反证据也不能默默丢，否则人永远不知道世界变了；标冲突回待复核，是让人再看一次，不是机器盖人。

**为什么 `50-Mine/` 模型不读。** 一旦模型读了人的判断，评估就会往人的判断靠，人就没有了独立的第二双眼；人要影响系统只能走有记录的入口，每次影响都可追溯。一线一文件而不是一题一文件，是因为问题会关、会并、述线会合并，文件跟着动就要软件改 `50-Mine/`，违背「软件永不进」。

**为什么不设封顶。** 用户定：先不设，用一段时间自己调。没有数据前的封顶是猜；排序不截断让要紧的在上面，看多少人自己定。这是在阅读负担红线上开的口子，所以入口页报总数、记录里记数，几周后拿数再看。

**为什么解挂只给机器事后生效的。** 人点过头的不需要解；4b 是每晚的大头，给勾就把初筛页变成待办清单。回顾整体的改挂那件只加不减，所以补「我提的 · 拿掉挂法」这条路。同一意图不在两处，是因为两处各收一次就会记两条、撤两次。

**为什么到期不靠人。** 应验与兑现是事实问题，核实层能判；人只在判不出时介入。预测要能被结果判，是预测打分的前提；靠人判就永远攒不出兑现数据。

**为什么翻旧账归核实。** 改判的三个来源（更好的来源、人复核、原来源撤稿）各有各的触发；定期抽查是花额度找没人要的改判，宁缺勿编。回顾整体管形状不管判定，把它塞进回顾就是两件事混一页。

## Consequences

- `SPEC.md` v4.1：§1.2 周末那一列改写成五条入口加写判断；§1.3 加周末一行「不封顶，入口页报本周总行数」；§5 加「勾的语法」一张表（页面 · 行 · 勾 · 附件 · 收走后写哪条记录）；§6 `40-Review/` 入口页加六页、`50-Mine/` 一线一文件；§8 红线 6 补「周末只读 `40-Review/`」，红线 7 补「`50-Mine/` 模型不读、评估标 AI 估计」；§9 人改改成 `verdicts.jsonl` 人改行，`[人改:: 日期]` 作废。
- 0011 Consequences 里「人改也是追加一条人改记录」照旧，只是载体从标签换成记录行。
- 新部件：收勾扩到六页与深加工页，入口页与六页的渲染，人改记录与传播，解挂，来源表与词表的人确认，「我提的」执行，插件单选强制（ready-for-human 票、须 Obsidian 实测）。
- 出票：周末那张纵切票 = 合成记录（台账 + 轮记录 + 回顾建议）→ 重画 `40-Review/` 入口页加六页 → 收一次勾（复核改判 + 审批 + 解挂 + 词表确认）→ 追加记录 + 传播出预警行，fake runner 零额度，排在深加工骨架票之后；插件单选强制单开一张；回顾整体的 prompt 不是 AFK 票。
- #90、#91 已改 needs-info：它们定的「人把候选行剪贴到词表文件」是人改文本当意图，与本 ADR 不合，随 SPEC v4 重写人机界面那半，候选攒法与 L2 输入块照旧。
- 原型第 10 步的「复核列」「人手改专题表」作废；原型述线页「我的判断 → 50-Mine」链接的位置保留。
- 按默认走、有数据再调：待复核「3 周未看」、各页排序、说话人「样本少」的 20 条、来源降级一档、入口页的总数怎么用。
