# 0010. 听错与黑话：L2 按依据分档，正字按词排队，词表回灌

**Date:** 2026-10-20（决定形成于 2026-10-11 至 10-20）
**Status:** Accepted

## Context

逐字稿里有两类字读者读不懂：

- **听错（ASR 生音）。** 人名、地名、英文被写成同音汉字。FireRed 换上以后这类更多（ADR 0006）。两集里 L2 标出的疑似听错 EP01 52 条、EP02 131 条。
- **黑话。** 主播用代称、缩写、假设人物指真实的人和事（没有新闻资质，直呼政治人物会被警告）。听错凭读音能改回，黑话要知道「这位主播用这个词指谁」，逐字稿里没有。

红线 2 写着「不引入外部知识纠正主播」。两次实验划出了边：

- **本地大模型改正本，否决（2026-10-11）。** 5070 上 9B、35B 给正本出建议：最好的一组 55 条确凿听错修好 4、改坏 0，但其余改动抽样 40 处错 26 对 13；三家引擎写法一致处改了音的 8 处全错。错法是把近期的人和事改回旧知识（新总统改成旧总统、新组织改成旧政党）。远不过约定的 1 : 5 门槛。报告在本机 `D:\asr-exp\REPORT-llmfix.md`，不进仓库。
- **L2 自己改，前后不一。** 旧 prompt 要求正文照原写法、只在末尾列「听成 → 应为」，实际有的名字正文已改、有的照旧，一个述段标题和正文各写一种。

另有两条路线上的事：按主播的词表（拼音滑窗候选加安全闸门）已出票 #90、#91、#89，是 ASR 侧的纠偏；「按主播区分的 prompt」是用户 10-14 提的方向，黑话要相关背景打底才读得懂。

2026-10-19 议深加工时用户提出：最初级的加工就是把生音、黑话换成正确的词，原稿保留，但人和后续程序读的都应该是改过的文本。先按「深加工的一道工序、按段做」设计；10-20 两处自纠：这是处理不是分析，该给所有读者用；工作量跟着新生词数走，不跟着「一集」走。

## Decision

1. **L2 对听错的写法。** 读音相近的名字，正文写改正后的，并且**必须**列进「疑似 ASR 生音」（听成 → 应为）；读音不近的照原样、不列，可能是主播口误，交给深加工核实。原话一律逐字（ADR 0009）。
2. **L2 对黑话按依据分三档。** ① 这位主播的黑话表里有（人确认过）、或本集主播自己点破了：正文写真实对象、代称放括号，列进「黑话」小节并写依据。② 只是模型推测：正文照原样，「黑话」小节写「可能指 X（推测）」。③ 不知道：只列。代称必须在本章切片里出现过（同 ASR 条目一样过闸门）。红线 2 补一句黑话例外：须写依据，推测不进正文。
3. **正字是每晚的处理阶段，在 L2 之后，不是深加工的一道。** 工作项是**词**：一个词全系统只联网查一次。先用词表和上下文定能定的，定不了的进「待查」队列，按出现次数、是否在说法里、是不是人名机构排。每晚按面板给的额度从队头取词联网查，结果进词表，状态为待查 / 定了 / 查过未定 / 人确认；查过未定的词再出现或过约 30 天才重试。含这个词的所有段靠文本操作补改字表，不调模型。模型只做两件：上下文歧义的判定，队头的联网查证；批按 token 切（ADR 0008）。
4. **产物是改字表，不改写整理稿。** 每段一张：原字、改字、类别（生音 / 黑话 / 人名 / 外文）、依据与链接、把握。JSON 里正文不动，笔记重画时套上去，改处可见（写成「正字〔听：原字〕」）；初筛页、述线页、深加工读的都是套过的文本；原话仍锚到逐字稿那一行。
5. **只改听错，不改说错。** 主播自己说错的人名、数字是说法，归深加工核实；正字只碰转写错误。
6. **人在周末扫低把握和查过未定的。** 确认过的进两份词表：整理用的黑话表（按主播分，下一集 L2 带上，算进 12 万预算）和 ASR 用的拼音词表（#90 那条线）。下一集从 ASR 起就对，不再查第二遍。
7. **本地大模型直接改正本不上。** ASR 剩下的错照旧归 L2 与正字。

## Rationale

**为什么分档而不是让模型放手改。** 本地大模型实验说明模型「纠错」的主要错法是拿旧知识套新人新事，三家引擎一致处还改错八成以上；大模型如此，L2 也不会例外。按依据分档，有依据的才进正文，推测只能放在小节里，链条不断。

**为什么正字是处理不是分析。** 情报流程里转写、翻译、实体还原都在分析之前，给所有读者用。放进深加工、按述线做，没被深加工的那一大半内容永远带着生音，每天读的初筛页先吃亏。

**为什么按词不按段不按集。** 同一个生音在一集里出现几次、在几集里反复出现，按段做就查几次；按词做查一次、全系统生效。工作量跟着「今晚新出现的生词有几个」走，一个主播的生词前几周多、之后是涓流，按集封顶既不准也不必要。

**为什么是改字表不是改写。** 改字表留着原字和依据，改错了能回退、能顺着依赖传下去（ADR 0011）；原话逐字的红线不受影响；读者和后续程序读到的仍是改过的文本，用户要的两头都占到。

**为什么回灌两份词表。** 一次联网换来的答案，下一集若再查一遍就是白花额度；进黑话表让 L2 直接写对，进拼音词表让 ASR 直接听对，两层各省各的。

## Consequences

- L2 prompt 改：听错的写法、「黑话」小节、代称闸门；`SPEC.md` §4 L2 的 `asr` 说明、新增正字阶段、红线 2 的措辞随 v4 改。
- 新文件：按主播的黑话表与词表（含状态与依据）、每段的改字表；渲染层加「套改字表、改处可见」。
- 10-14 定的「推测黑话交深加工联网查」改为交每晚的正字；深加工核实只在某条说法被一个词卡住时再查。
- 「按主播区分的 prompt」落地为 L2 输入里的这位主播的黑话表，占的 token 算进预算。
- #90、#91、#89 的词表多一个来源：正字确认过的词。
- EP01 要按新 L2 prompt 重跑对照（人在场改 prompt，不进 AFK 夜跑）。
- 正字的联网额度是面板上的旋钮之一，和深加工共用（0014）；没查完的词留疑似标记，文本照样可读。
