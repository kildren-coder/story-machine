# 0002. 队列笔记即状态机，worker 只是执行器

**Date:** 2026-08-03
**Status:** Accepted

## Context

SPEC §10 第 1 条要「一句命令，音频进逐字稿出」。实际要走四步、跨两台机器：

```
下载（PC / yt-dlp）→ 转写（PC / faster-whisper）→ 取回（scp）→ 建 EP 笔记（笔记本）
```

一集三小时音频，全程约十分钟。中间任何一步都可能失败（网络、风控、CUDA、磁盘），而失败点决定了该从哪重跑——重跑整条就是白烧一次 GPU 和一次下载。

同时人明确要求：**在一个专门的 Obsidian 页里管理，粘链接就开跑，能看见进度**（不接受"另开终端看日志"这种形态）。

于是有两个问题要一起回答：状态存哪、进度怎么显示。

## Decision

**队列笔记 `_pipeline/队列.md` 是流水线的唯一状态。** worker 无状态，插件也无状态。

一行一集，状态写在括号式 inline field 里：

```markdown
- https://www.bilibili.com/video/BVxxx [ep:: EP01] [阶段:: 转写中] [进度:: 43% (01:01:20/02:21:25)] [更新:: 20:58:12]
```

- `阶段` 是状态机：`待下载 → 下载中 → 待转写 → 转写中 → 待取回 → 取回中 → 待建笔记 → 建笔记中 → 完成`，外加终态 `失败`。
- **`scripts/worker.ps1` 是执行器**：读队列 → 推进第一个有待办的行 → 每完成一步改写该行。
- **`obsidian/story-machine-pipeline` 是渲染层 + 启动器**：把队列文件画成面板，点「运行」时 `child_process.spawn` 拉起 worker。它不持有进度。
- **`pc/smpc.py` 是 PC 侧执行器**，子命令 `download` / `transcribe`。

配套两条契约：

- **跨 ssh 的参数一律纯 ASCII，中文只走文件。** B 站标题必然带中文，经 ssh 的 argv/stdout 会撞 PC 端 PowerShell 5.1 的代码页。所以 PC 侧产物一律落 `E:\asr\staged\EP{n}.*`（ASCII 名），标题等元数据写进 `EP{n}.meta.json`，由 scp 取回后本地解析。`EPxx` 是跨机唯一标识。
- **stdout 只走 ASCII 协议行**：`PROGRESS <已完成> <总量>` / `INFO <文本>` / `ERROR <文本>`。worker 逐行解析。

## Rationale

**为什么状态在文件里而不在进程里：** 这条流水线的失败是常态不是例外，而"从哪一步重跑"恰恰是最值钱的信息。状态落文件让崩溃恢复变成一行代码——worker 启动时把卡在「\*中」的行打回对应的「待\*」。进程内状态则需要额外的持久化机制，而那机制最终还是要落到一个文件。

**为什么进度不需要 IPC：** Obsidian 检测到磁盘变更会重载文件并触发 `vault.on("modify")`。worker 写队列 → 面板重画。插件和 worker 之间因此**不需要任何进程间通道**——面板下方那个日志窗只是排障用的副产物，关掉不影响状态正确。这是把状态放进 vault 换来的，不是设计出来的。

**为什么用括号式 inline field 而不是 JSON/YAML：** `proto/dataview-rowlevel` 那轮已经验证过这套写法能被 Dataview 行级查询（续行式不成立）。用它意味着队列**天然可查询**——控制台笔记里的「进度总览」表就是一条普通 Dataview 查询，不是插件画的。同一套语法既是数据模型又是运行时状态，少一套格式要维护。

**为什么不用现成的 Shell commands 插件：** 那类插件能跑命令，但状态和进度还得自己解决，省下的只是 `spawn` 那十行。而 ADR 0001 的教训是通用插件的模型和我们的模型对不上时，配置绕不过去。

**分成两个插件：** 拉子进程要 `require('child_process')`，必须标 `isDesktopOnly: true`；没必要让纯渲染的 `story-machine-timestamps` 跟着降级。

## Consequences

- **不装插件也能用。** 直接在队列笔记敲 `- <链接>`，终端跑 `.\scripts\worker.ps1`，效果完全相同。插件是便利层不是必需层——这也意味着插件坏掉不阻塞流水线。
- **队列文件有写冲突的理论窗口**：插件追加与 worker 改写之间。缓解是插件只追加裸链接（`ep`/`阶段` 全由 worker 补），把契约做薄；worker 每次 `Save-Row` 都重读全文件按行号替换。窗口是毫秒级，代价是极小概率丢一次入队。
- **进度写入要限流**（当前 2 秒）。写太密会让 Obsidian 反复重载，编辑该文件时光标会跳。
- **`_pipeline/` 是运行时状态目录，不是内容**，SPEC §6 已补。它不参与图谱。
- **说话人分离留了空槽**：转写产出 `speaker: null` + `diarization: "pending"`，词时间戳存 PC 侧 `EP{n}.words.json`。补跑分离时不必重转一遍。
- PC 侧从 15 个 `bench_*`/`test_*`/`exp24` 实验件收敛成一个 `smpc.py` 生产入口，进 git、可重新部署。
