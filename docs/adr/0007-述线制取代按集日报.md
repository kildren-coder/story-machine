# 0007. 述线制取代按集日报：跨集收纳、初筛页把关

**Date:** 2026-10-20（决定形成于 2026-10-09 至 10-19）
**Status:** Accepted

## Context

ADR 0003 把产物定成**日报**：一天一篇，L4 把当天各集的话题聚成事件，每个事件一张六问卡，跨天的事落在 `30-Events/` 的事件笔记里。里程碑 1（L1 到 L3）按这个形状跑通了两集。

2026-10 初用户提出第四次定位。用户要的不是「昨天讲了什么」，而是**把大量直播、乃至其他媒介的信息串起来**：同一件事隔几周再被谈起，要能接到一起看。按天聚事件做不到这一点，「天」是处理日期，不是内容的单位；事件按天定义，同一件事会被切成好几个事件。

2026-10-09 做了一个原型（本机 vault 的 `_lab/thread-proto-20261009/`，含整理稿与页面，不进仓库）：挂述线、初筛页、述线页、按需深加工各一层，拿已有的两集真跑。一条谈美国左翼组织的述线跨两集全部命中，11 段 2 集。之后用十天按「一步一个子对话」核实了原型的第 0 到 6 步，每步拿两集的真材料看例子、由用户判对或要改。本 ADR 记这轮核实里关于**组织单位与阅读面**的决定；上下文预算与本地索引见 ADR 0008，原话抄定见 0009，听错与黑话见 0010，记录只追加见 0011；深加工本身见 0012，说法台账见 0013，深加工调度见 0014，人的入口与周末复核见 0015。

核实中量到的几件事：

- **词撞车。** 主播自己说「专题」「话题」「议题」：两集逐字稿里分别 7、5、11 次；EP01 的 L1、L2 产物里已经带进 18 处主播嘴里的「专题」，而挂述线那层读的正是这些标题和说明。
- **一段只能挂一条，述线就缺东西。** Opus 复核 EP01 的 37 个话题：切点 32 个对；有 3 个话题里夹着约一分钟属于另一条线的总立论或比喻，因为「一个话题最多挂一条」，另一条线就少了它；挂述线的理由里自己写过「也可能该并入另一条」，却只能二选一。
- **没挂的不少。** 两集 80 个主段有 15 个没挂上任何一条（EP01 4 个，EP02 11 个，其中约 20 分钟是成套的理论段）。
- **页面上的「起止」误导。** 一条散在整集的述线写成 00:08 到 02:20，看着 133 分钟，实际 31 分钟。
- **整理稿的定位变了。** 用户定整理稿是「按话题查的完整记录、能代替收听」，全比短重要；v3 的压缩比 0.2 作废，实测约 0.5 可接受。

## Decision

1. **组织单位是述线，不是天；时间单位是一次运行，不是一晚。** 述线是跨集的收纳处（代码里仍叫 `thread`）。每次运行的产物是**初筛页**（全系统一页，见第 5 条）和**述线页**（一线一页）；日报、`20-Daily/`、`30-Events/`、导语层 L6 退役。每条记录带运行 id 与时刻。本文和 0008 到 0011 里的「每晚」「当晚」「那晚」指目前每天夜里跑一次的节奏，结构上的意思都是「那次运行」；系统往持续喂新闻与直播的流水线走时，节奏变、结构不变。
2. **术语与主播的词分开。** 一集 → 章节 → **述段**（原「话题」，整理稿里的一节）→ 三档**主段 / 旁段 / 空段**（即 `talk` / `aside` / `filler`）→ **挂**（**加挂**：在原有之外再挂一条；**改挂**：迁移；**回挂**：把以前没挂的旧段拉进来）→ **述线** → **述线页**、**初筛页**。代码与数据里的英文标识符不变。
3. **挂法。** 主段与旁段都挂，空段不挂。一个述段可以挂多条，门槛只有一条：**能帮人理解这条述线才挂**，顺嘴一提的不挂。「已有述线优先」只管同义，已有的装不下时不许硬挂；理由里想写「也可能该归 X」，X 在清单里就加挂，X 不在清单里、往后又会反复谈就开 X。回挂当晚生效、不用人点头，页面标「回挂」给链接，人觉得不对周末解挂。
4. **述线怎么划。** 看内容定，不看主播说没说以后再讲。范围词（美国政治、民粹）不算；单条说法不算，归它所属的那件事；**一套说法算**，条件是一句话能说出主张、且按内容看拿它解释过不止一件事。开具体的事，不开笼统的「中美关系」。起名以说清楚为先，不求短，可以是问句；说明里每一项都必须是名字那件事的一部分，「也暂归此」「含由他引出的」不许写；说明开线时写，之后每晚不改，要改走回顾整体。述线之间**不分上下级**；述线页有一节「关联述线」，标「其中的一部分 / 属于 / 有关联」，只是页面标签，不改挂的规则。
5. **人的把关面是初筛页：全系统一页，按处理日分块，新的在上。** 同一天的几次运行并进同一块，每次运行重画这一块时按记录重算；旧块怎么折叠、多久搬进归档页归 SPEC。块里：这天跑了哪几集每集一行头（集号、播出日、时长、主播、挂上几段没挂几段；补跑的写「补跑 · X 播」）。述线按这天的分钟数从多到少排，标题行写段数与分钟数，新线给一行说明，续线给一行底细（上次更新、累计几段几集、深加工过没有）。述段行只给标题和整理稿链接，说话人只在多人集写，旁段、回挂标出。所有述线之后是「没挂的述段」一节（主段旁段放一起），空段进折叠栏供检查有没有判错。每条述线标题下一个勾「深加工这条」（调度见 0014）。人可以**预开**述线：给名字、可不写说明，当晚挂述线的那层就能看到它，旧段靠回挂拉回。
6. **述线页节次**：说明 → 底细 → 现状 → 关联述线 → 时间线 → 深加工记录 → 我的判断。时间线由代码从记录重画、按播出日期排，组头写「播出日 · 集号 · 主播」；人写的东西放节外，「我的判断」落 `50-Mine/`，软件不碰。
7. **整理稿保留在 EP 笔记里，只给人看**，是初筛页、述线页、深加工页「→ 整理稿」链接的落脚处；每个述段节带块 id `^t-<述段 id>`。L1、L2 一般不重跑；要重跑就当这一集换了一版切法：集号、播出日、节目内时刻不变，旧切法的述段、挂法、改字表作废，重挂并重画这一集在初筛页和述线页上的行；深加工轮次与说法台账不擦，引用旧述段的靠时刻重新对到新述段，轮次标「基于旧切法」。
8. **补跑的旧集进处理它那天的块。** 初筛页是人把关哪些内容值得接进系统的地方，块按处理日分，不按播出日。
9. **回顾整体每周一次**，做五件事：合并、拆分、改挂、改名改说明、没挂的述段整成述线。只看本周碰过的述线和本周新增的没挂述段；每件先本地检索再让模型判。只增加东西的（整成新线、加挂、新关联）自动生效、周末页提醒；合并、拆分、拿掉挂法、改名改说明先走审批，人点头后代码执行，按类记点头与驳回次数。

## Rationale

**为什么按述线不按天。** 用户要串的是「事」，事横跨几周几集；天只是流水线跑的那一晚。日报把同一件事拆到好几天里，事件笔记又只能按天追加，两头都接不上。述线把「这件事到现在说过什么」放在一页上，补跑旧集也能插进去。

**为什么是初筛页而不是日报。** 人每天的活是**挑**，不是读完。六问卡那种深加工内容按需才做（0012 到 0014），塞进每天必读的页面就是阅读负担；初筛页只回答「今晚来了什么、挂到哪条线、值不值得深加工」。述线页才是读内容的地方，按线读、要读时读。

**为什么时间单位是运行、初筛页只有一页。** 一晚一次只是现在的节奏；系统要往持续喂新闻与直播的流水线走，一天可能跑几次。记录按运行记、页面按处理日聚，节奏怎么变都不用改结构。一页而不是一天一个文件：人只盯一个地方，没处理的勾和没挂的述段不会因为哪天没看就埋在旧页里，收勾也只扫一页。

**为什么重跑当换版而不是追加。** 整理稿有标准答案（逐字稿），两次跑出来的差别是质量不是判断，留着旧版没有用；深加工是一轮轮攒出来的判断，才需要只追加（0011）。

**为什么旁段也挂。** 旁白里的信源常比旁白本身有价值；每集只提一句的事，单看一集判不出会不会再谈，要在以前的片段里看到它反复出现才知道。深加工只拿旁段的信源当线索、不核它的说法。

**为什么一段可挂多条。** 「一段一条」逼着模型在两条都对的时候二选一，缺的那条永远不知道自己少了什么；原型里自己写出「也可能该并入」的理由就是信号。门槛放在「能不能帮人理解」上，顺嘴一提仍然不挂。

**为什么不分上下级。** 上下级逼着每条新线先回答「归谁」，而「一部分」和「有关联」在页面上用标签就能表达；真正的同一件事换说法交给回顾整体合并。

**为什么开线看内容、不看「以后还会讲」。** 模型预测不了主播以后讲什么；一套反复用来解释别的事的说法，本身就是理解这位主播的背景，和具体的事一样值得成线。

**为什么起名可以长。** 名字给没听过这场直播的人看，压缩过的名字（把一句主张缩成几个字）读不懂；主播自己起了名的用主播的名。

**为什么术语要改。** 挂述线那层读的是模型写的标题和说明，里面混着主播说的「专题」；我们的结构词和主播嘴里的词必须分开，否则模型分不清谁在说谁。新词在两集逐字稿和产物里都是零次。

## Consequences

- `SPEC.md` 全量重写为 v4，走「备份 commit → 删备份 commit」两步；分两趟：v4.0 覆盖阶段 0 到页面（本 ADR 与 0008 到 0011），v4.1 补深加工。`CONTEXT.md`、`CLAUDE.md` 的「日报」字样随之改。
- 红线 6「人每天只读日报」改成「人每天只读初筛页」，深加工页与述线页按需读；红线 5「核查不改整理」不受影响：正字不是核查，改字表也不改 JSON 正文，只在画笔记时套上（0010）。
- 流程表变：L4 事件聚类换成挂述线的三次小调用（0008）；L6 导语退役；L7 渲染改画初筛页与述线页；L5a、L5b 的形状由深加工框架重定（0012）。
- vault：`30-Threads/<述线名>/` 一线一个文件夹；初筛页一页，位置、旧块折叠与归档的门槛随 SPEC v4 定；`20-Daily/`、`30-Events/` 不再生成。
- 每条挂法记录带集号、述段 id、播出日期、节目内时刻、挂上的运行 id 与时刻、怎么挂上的（4b / 4c 回挂 / 回顾整体 / 人），任何排法都能从记录重算（0011）。
- 阅读预算改写：整理稿按「完整记录」定位，压缩比目标 0.2 作废，字数预算不再是硬指标。
- 多 UP 的形状本轮没有重议，随 SPEC v4 定。
- 事件制旧票 #57、#60 到 #63、#66、#68、#71、#73 已于 2026-10-16 关闭；按述线制重出。
- 原型的页面、vault 副本、脚本留在本机 `_lab/`，含逐字稿片段，不入库（红线 10）。
- 回顾整体五件事的标准、相似度门槛、每周封顶条数要拿真数据定；「一部分 / 有关联」怎么分清是 prompt 活，不是 AFK 票。
- **2026-10-25 补（#95 基准人核）**：第 3 条「顺嘴一提的不挂」定成可操作的尺子：兼要有一个判断加理由、或一件事的经过；一句提及、复述上一段、预告、提问都不算。两集按这把尺子两轮人核出 27 条述线、147 条挂法（主 81 / 兼 66），是召回率的分母（0008 补记）。人核时冒出三件待 SPEC v4 议：预告与指向要不要多一档「指」（述线页「另见」一行，不进时间线）、述线页要不要分节、挂述线时模型拿不准的事实疑点要不要进初筛页。
