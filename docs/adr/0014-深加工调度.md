# 0014. 深加工调度：勾只是标记，面板管时机

**Date:** 2026-10-23（决定形成于 2026-10-19 至 10-23）
**Status:** Accepted

## Context

原型（2026-10-09）的深加工靠命令行触发：`worker.ps1 -Deepen <英文 id>`，一条述线一次，人从初筛页「想深入哪条」那节抄英文 id 到终端。跑通了（一条两集的述线一次约 2.4 美元、11 分钟），但「什么时候跑」没有设计：

1. 触发在终端不在页面，初筛页为此列了一张英文 id 表给人抄。
2. 一次只能跑一条：没有队列，没有暂停，撞到订阅额度上限就是报错。
3. 深加工与每晚整理、每周回顾整体之间没有先后。回顾整体改挂法时某条述线正在深加工，材料就对不上，轮记录说不清基于哪版挂法。
4. 什么都不自动提议。0012、0013 定了三种预警（指标到期、新段撞上缺口、新说法与已核事实相抵），出来之后谁去重跑、什么时候重跑没人管。

这期间定下的几件事都要求调度是单独的一层：0008 第 6 条要每个阶段先答「工作项、缓存、旋钮」三问，额度旋钮在面板；0010 定正字的联网额度与深加工共用一个旋钮；0012 第 4 条的「缺口再转一圈」也是旋钮，第 12 条写了「排队不设自动排法，先勾先做加面板手动拖」；0013 第 3 条核实按 token 切批、没核到的留队列。2026-10-19 用户定**打勾只是标记要做，什么时候跑由深加工面板管**，并提出面板要看全系统进度、手动开停、调并发、拖动排序，回顾整体与深加工要错开；10-22 第 9 步定了写回与并发的规矩；10-23 第 10 步定了三种自动触发都只提议、不自己跑。本 ADR 只管「什么时候跑、跑几条、撞了怎么办」：跑什么见 0012，台账见 0013，人怎么点见 0015。

## Decision

1. **勾只是标记，面板管时机。** 「深加工这条」的勾在初筛页每条述线标题下、述线页底细下（0007 第 5、6 条），人在 Obsidian 里点，带一句「问：___」（0012 第 1 条），空着就是默认问题。worker 每次运行**先收勾、再动任何页面**，收走的行改成「排队中 · 日期 勾 → [[深加工]]」。收勾只认行首的 `- [ ]`，扫全部初筛页（含折叠块与归档页）与述线页，只扫文本、不花额度。命令行 `-Deepen` 留作后备与排查用。
2. **队列一行 = 述线 + 问题，状态在 `_pipeline/深加工.md`。** 这是 ADR 0002 队列笔记的扩展：一行一项，括号式 inline field 记状态（待跑 / 在跑 / 暂停 / 等额度 / 完成 / 失败）、勾于、勾过几次、勾时几段 · 现在几段、做到哪次调用；插件只画面板、拉进程，不装插件也能在笔记里改文字挪顺序、改状态。同一条述线的几题排在一起时一次跑：列假设一题一次、核实队列按命题合并去重、推理与反方各题一份（0012 第 1 条）。一条述线的一题在队列里只占一行：几处都勾、隔几天又勾都并进这一行，记勾过几次；已在排队或在跑的，新画的页面不再给勾、直接写状态。做完再勾算新的一次；上次深加工之后没新段的，面板标出来，跑不跑由人定。
3. **先勾先做，加面板手动拖，不设自动排法。** 顺序只有这两个来源。按分钟数、按诊断力、按到期之类的自动排法等有数据再议。
4. **材料在开跑那刻取，不在打勾那刻。** 开跑时记下用了哪几段（含切法版本，0007 第 7 条），跑的中途新挂上的不进这次；面板写「勾时 11 段 · 现在 14 段」，做完述线页底细写「深加工 日期（14 段）· 之后新增 n 段」。排队时这条线被合并就跟着留下的那条走，两条都在排就并成一行；拆出的新线不自动排。
5. **开始与暂停的粒度。** 面板上的开始 / 暂停是队列的总开关：开着时每次运行按并发消化队列，暂停时只收勾不跑。暂停 = 调用之间停：当前那次调用做完就停，下次从没做的那次接着；另给「立刻停」，白扔当前那次调用。中途断了（关机、报错）同暂停：从没做的那次调用接着跑，不从头，记录只追加、页面派生，重画一遍即一致（0011）。轮记录最后写、写完才算这轮成立，半份不写。
6. **并发默认 1，上限 3。** 共用述段的两条述线不同时跑（事实核一次被引用，0013 第 7 条）。写回排队一份一份写：写回前取 `_pipeline/.write-lock`，超时 30 秒重试；页面是记录的纯函数、整块替换、谁后画谁赢。深加工可以和每晚整理同时跑：材料开跑时取走，写回只碰 `ledger/*`、`questions/*`、这条线的述线页块、深加工页、每线台账视图、初筛页预警节和面板的一行；记录文件按写者分，`ledger/*`、`questions/*` 只有深加工写，`links / threads / runs / EP{n}` 只有整理写，同一记录文件永远只有一种写者。
7. **额度一个旋钮，三处共用。** 正字的联网查证（0010）、深加工的四次调用（0012）、缺口再转一圈（0012 第 4 条）共用面板上同一个额度旋钮；各自的队列按优先级消化，没做完的顺延。撞上订阅额度上限自动暂停整队，标「额度用完」、不算失败；报错带恢复时间的到点接着跑（要实测；剩余额度能否读到要查）。
8. **与回顾整体错开。** 到点要跑回顾整体时有深加工没跑完（在跑、排队都算），回顾不跑，面板给提示说明，人确认仍要跑才跑。深加工都跑完后面板提醒「30 分钟后自动跑回顾」，到点自动跑，倒计时里可点「现在就跑」或「先不跑」。人确认先跑回顾时，在跑的那条照跑完（回顾期间新挂上的段算之后新增），回顾跑的过程中不开新的深加工；回顾提出的改动人点头执行时碰到在跑或在排的那条线，放回待执行并在面板标「等 X 跑完再执行」，下次运行再试。
9. **自动触发只提议，不自己跑。** 三种触发都由代码在每次运行里算、零额度，落成初筛页顶部「预警」节与述线页「现状」下的预警行；带动作的行行首一个勾「重跑问 N」，旁边一个「不重跑」（0015 第 2 条）；提议被人勾了才进队列，和手勾的一样排。
   - **到期**：指标、预测类假设、预测台账条目三种到期合一，都须是日期（事件型由列假设换算并标「约」；到期那天核实判「没发生」就顺延 30 天并记一笔）。每次运行代码扫到期，生成派生命题「X 发生了没有 / 结果如何」排进核实队列头；核实判完，代码写指标的应验（撑 / 反 / 两可）或预测的兑现（兑现 / 落空 / 两可），不靠人；判两可或查不到的上待复核。判出结果出预警行。面板开关「应验后自动排队」默认关，几周后人几乎全勾再改自动。
   - **新段撞上缺口**：每次运行 L2 之后，新述段的说法与实体去撞开着的「想听主播讲」「要的数据」类缺口和「查不到」清单（本地检索，零额度，0008）；实体键命中加相似度过阈值才算撞上，阈值归检索调研票。不设封顶，按题合并：一题每次运行至多一行，行里列全部撞上的时刻。撞上 = 缺口状态标「可能已补 · EP@ts」、预警行不带勾、下次这题重跑时代码把撞上的段列进「本轮新增」；撞到「查不到」清单的命题提前进 30 天重试队列。
   - **新说法与已核事实相抵**：说法匹配判冲突（0013 第 7 条）、改判传播让评估过期（0013 第 8 条）各出一行；过期行带「重跑问 N」勾，冲突行没有可勾的动作，只放 ⚠。
10. **运行约束。** 订阅额度是一个池子：每晚整理、正字、深加工、AFK 夜跑（一晚只开一个 loop）、交互会话都从它出，第 7 条的自动暂停保护的就是这个池子，旋钮是人给正字与深加工的份额。5070 不在线时索引与挂述线跳过、下次补（0008 第 5 条），撞缺口要本地索引，同样这次不撞、下次补；深加工的检索层（AnySearch）不在 5070，不受影响。现插件只许一个 worker 在跑，深加工由 worker 另起的进程消化队列。深加工不进 `-Watch` 的自动流转（0002 补记），勾与面板是入口。

## Rationale

**为什么勾只是标记。** 人点勾的时候不知道额度剩多少、别的队列排到哪，「什么时候跑」不是人在那一刻能定的事；把意图和时机分开，勾随时可以点、面板统一管跑。收勾先于重画是因为页面是派生的（0011），不先收，重画就把勾盖掉。

**为什么状态在队列笔记。** ADR 0002 的原则原样适用：状态在文件里，显示免费，崩溃可续跑，不装插件也能用；再给深加工一套进程内状态就是两份状态。0002 补记说队列只管阶段 0，是因为 L1 到 L3 产物即状态；深加工是人勾出来的、要排队、要暂停、要并发的活，产物即状态不够用，所以另开一个队列笔记，不往阶段 0 的队列里塞。

**为什么一行是述线加问题。** 深加工的单位是问题（0012）；同线几题一起跑省掉重复的核实；一题一行天然防重复跑，几处勾、几次勾都落到一行上。

**为什么不设自动排法。** 自动排法要知道人想先看哪条，现在没有这个信号；先勾先做最可预期，手动拖给人改主意的口子。等队列真的排长了、有了「人每次都把哪类拖到前面」的数据，再谈排法。

**为什么材料在开跑时取、中途不加。** 打勾到开跑之间可能隔几次运行，用勾时的材料就是拿旧材料做新判断。但跑的中途不加，否则一轮之内材料不一致，轮记录说不清用了哪几段，改判传播也对不上版本。

**为什么暂停在调用之间。** 一次调用是不可分的额度单位，中途停就是白扔；调用之间停不丢任何工作。「立刻停」留给额度告急的时候，代价写明。

**为什么并发默认 1。** 订阅额度一个池子，并发 3 条只是把同样的额度花得更快；共用述段的述线互相引用判定，同时跑就有先后之争；写回要排队。1 够一个人用，上限 3 留给补跑旧集攒了一堆的时候。

**为什么一个旋钮。** 正字、深加工、缺口再转一圈花的都是同一个池子里的联网与模型调用；分三个旋钮，人每晚要调三次，还要自己算总和。0008 第 6 条要的「旋钮在面板」就是这一个。

**为什么错开。** 回顾改的是述线的形状（合并、拆分、改挂），深加工读的是述线的材料；同时跑，一边改一边读，轮记录说不清基于哪版挂法。用户的话：没额度本来就没法回顾。30 分钟是给人一个窗口，能在回顾前再勾一条或先不跑。

**为什么只提议、不自己跑。** 重跑花额度，花在哪由人定；系统自己排队会把队列塞满人没要的轮次，初筛页的预警行就成了噪音。撞缺口零额度，所以每次运行都算，但它只是线索、不是动作，不带勾。「应验后自动排队」默认关、几周后看人勾不勾再改自动，和 0007 第 9 条「审批先看看再改自动」是同一条路。

## Consequences

- `SPEC.md` v4.1 的 §4.2「触发与调度」重写：深加工队列笔记、面板、开始 / 暂停、并发、额度旋钮、与回顾整体错开、三种自动触发；§6 加 `_pipeline/深加工.md`、`_pipeline/.write-lock`；§7 模型表加旋钮与并发一列。
- ADR 0002 的「队列只管阶段 0」补记不改：深加工有自己的队列笔记，不进阶段 0 的队列；L1 到 L3 仍是产物即状态。
- 新部件：收勾（扫初筛页、述线页、深加工页，含折叠块与归档页）、队列笔记读写、深加工进程、额度检测与自动暂停、到期扫描与派生命题、撞缺口的本地检索、预警行渲染、面板（`story-machine-pipeline` 插件的改动是 ready-for-human 票、须在 Obsidian 实测、不进 AFK）。
- 要实测的：额度报错带不带恢复时间、剩余额度能否读到、30 分钟倒计时、并发大于 1 时的写锁。
- 按默认走、有数据再调：30 分钟、并发 1 与上限 3、写锁 30 秒、撞缺口的相似度阈值（检索调研票）、「应验后自动排队」默认关。
- 出票：第 6 步那张（打勾、面板、插件实测）；到期与撞缺口随周末那张纵切票与深加工骨架票（0015 Consequences）。
- 原型的 `-Deepen` 入口降为后备；初筛页「想深入哪条」节与英文 id 表删掉（0007 第 5 条已定）。
