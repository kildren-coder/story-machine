## 开跑前（三步，不能省）

1. Obsidian → **以库的形式打开文件夹** → 选中 `proto-vault` 这一层
2. 设置 → 第三方插件 → **关闭安全模式** → 社区插件市场 → 安装并启用 **Dataview**
3. Dataview 设置里打开 **Enable Inline Field Highlighting** 和 **Enable Inline JavaScript Queries**（后者非必需）

> 查询只在**阅读视图**（`Ctrl+E` 切换）里渲染。在编辑视图里看到的是代码块，不是失败。

## 这次实验不会「失败」

值得先说清楚，免得盯着 A 的结果紧张：**没有「方案作废」这个结局。**

实验 A 的 V6（全部字段挤一行、括号式）几乎不可能失败，而 SPEC §5.1 已经声明
「EP 笔记是容器不是阅读界面」——所以退到 V6 的代价只是 markdown 源码更难读，
而那本来就不是给人读的。

真正有价值的产出是**下面这三类结论**，它们都不是「行不行」而是「怎么写」：

1. **写法定稿**（4 空格 / Tab / 括号式）→ 直接写进 `prompts/stage2-extract.md` v0.2 的输出格式
2. **一组硬约束**（比如「自由文本只许用中文逗号」「归因作者不详时留空而不是写未具名」）
   → 每一条都机械可检，正好做成出口闸门
3. **SPEC §6.2 四条查询的定稿版本**（中文键要不要方括号、要不要 `LIMIT`）
