# PROTOTYPE · Dataview 行级查询验证

**丢弃品，不并回 main。** 分支：`proto/dataview-rowlevel`。

## 问题

`SPEC.md` §5.1 提出「一条断言 = 一个带行内字段的 list item」，字段写在缩进的续行上：

```markdown
- **A-02** 911 后小布什长期担心被斩首，因此设立八人帮作为指挥「备份」
    type:: causal
    情态:: 确定
    实体:: [[小布什]], [[美国国会八人帮]]
```

**这种续行写法是否真的被 Dataview 挂到父 list item 上，尚未实测**（SPEC §5.1 的 ⚠️、§11 第一条）。
若不成立，`FLATTEN file.lists AS L` 的整套跨集查询——也就是 SPEC 说的「总库不是一个文件，是一条查询」——就没有载体。

顺带验四件必然要撞上的事：中文字段名能不能点号访问、`contains` 会不会子串误召回、
自由文本里的英文逗号会不会把 `cause`/`effect` 切成列表、几千行时的手感。

## 怎么跑

```
python docs/prototypes/dataview-rowlevel/build.py
```

然后用 Obsidian 打开 `proto-vault/`，装 Dataview 插件，读 `00-先读我.md`。

## 设计上的两个刻意选择

- **实验 B 全用括号式写法**，不用续行式。B 问的是「值被解析成什么类型」，
  与 A 问的「字段怎么贴到行上」正交，绑在一起会让 A 失败时 B 也白做。
- **每行第一个字段是 `[probe:: Vx]`，纯 ASCII、括号式**，保证一定能解析。
  这样失败的变体仍会出现在结果表里（只是列为空），而不是整行消失——
  否则「解析失败」和「样本没写」在结果里长得一模一样。
