# 原型：多 UP 主日报（2026-09-11）

**问题**：新定位下「日报」长什么样，才是用户想要的效果？（三种版式可切换，`?variant=A|B|C`）

**素材**：EP02《瓜熟迪落拉》2026-08-02 直播录播（3h10m，瓜哥 × 历史哥），真实逐字稿。

**流程（都是 sonnet 子代理）**：
1. 逐字稿切三块（约 60 min 一块，粗时间戳一段一个）→ 每块一份整理稿草稿 `EP02-chunk*.digest.md`
2. 我把草稿转成页面数据 `frag-c*.json`（限定词标 `<hedge>`，说话人标 `<who>`）
3. 挑三件事派联网核查 → `check-A/B/C.json`（每条判定带 URL；ok/warn/bad/none）
4. `assemble.py` 合并 + 给每条原话补逐字稿片段 + 机械核对引文逐字命中（闸门 1）→ `daily-proto.html`

**发布**：https://claude.ai/code/artifact/692b935d-3031-4f99-8d43-e6e70995dc60

**结论（2026-09-11）**：用户选 **B「按事件读」**（事件索引 → 每事件六问卡 → 其余话题只整理 → 跨 UP 对照 → 信源）。评价「比预想的好、更实用」。A/C 弃用，C 的旁注形式可作为六问卡内的次级样式备选。

**过程教训**：
- 子代理必须显式 `model: sonnet`，默认继承 Fable 几分钟烧光月度上限。
- 一个代理一口气整理 60 分钟的块 = 单次输出 4–6 万 token，跑 30–47 分钟，且会撞 64k 输出上限。正式流程改成骨架层 → 逐话题层（每次只喂该话题切片），闸门放在层间代码里。
- 时间戳前缀只占输入 token 约 7%，不是杠杆；说话人改为只在切换处标即可。
- 阅读时间：正文 1.2 万字约 25–30 分钟，对比直播 191 分钟；核查台账另加约 1 万字。
