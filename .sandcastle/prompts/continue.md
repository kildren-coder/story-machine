## 铁律（与首轮相同）

- **测试前台阻塞跑，不要后台**。你是串行的，后台化只会诱发轮询白烧 token。
- **子 agent 只用来隔离大块探索**（同步开）；不要为并行开多个。
- **红线 10：逐字稿片段不进仓库**，样例必须是合成的。
- 红线 2 / 3 / 5 / 9 在代码里的形态：闸门只删不改、只报警不修正；渲染不改写
  整理层文字；派生文件带 provenance，失败单元进 `_failed/`。
- issue 的每一条验收标准都必须映射到至少一个通过的测试。
- `prompts/*.md` 改了必须升首行 `version:`。
- **动了契约就同步 SPEC**：文件增删改名、输入输出、字段、闸门规则变了，同一
  分支里更新 `SPEC.md` 对应条目（只写「做什么」）；纯改逻辑不碰它。
- 小步提交，commit message 说明「为什么」。本轮的 commit 直接叠在分支已有的
  commit 之上，**不要 rebase、不要 amend、不要 force push** 前一轮的历史——
  评审和人都要靠 `git log` 看出这一轮改了什么。
- 不修改与 issue 无关的文件；不动 `.sandcastle/`。**不要读 `.sandcastle/`**。
